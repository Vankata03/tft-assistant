## Destination

An MVP spec for a personal TFT coach, ready to hand to build sessions. The coach reads game state automatically and covers every v1 decision: econ, leveling and rolling, shop buys, transitions and pivots, items, augments, positioning, and carousel and opener choices. It runs in two modes: Baseline mode shows Guides and highlights within Riot's policy as approved apps apply it, and the opt-in Live mode gives advice computed from the live game. Output appears in an overlay, on a second screen and as voice callouts, and a post-game review replays each finished game against the engine. Success is measured as average placement over 50 games without the coach, then 50 games in Live mode.

- **Hardware** (owner's PC, checked 2026-10-04): AMD Ryzen 7 7800X3D, 32 GB RAM, AMD Radeon RX 6800 (16 GB VRAM, no CUDA). Any local model shares this GPU with the running game.

## Decisions so far

<!-- one line per closed ticket: [title](link): gist -->

- [Current TFT set and its mechanics, including wisp](005-current-set-mechanics.md): Set 18 (Enchanted Wilds, patch 18.3); the Wisp is a per-round shop purchase that changes econ, XP and roll odds, and its tables change every patch.
- [Automatic game-state capture options for TFT](003-game-state-capture-options.md): Overwolf game events cover almost all state (needs Overwolf developer access; augment keys forbidden); screen capture is the only Overwolf-free route; Riot's port 2999 API is unusable for TFT; memory reading is blocked by Vanguard.
- [Riot third-party app policy for real-time TFT advice](002-riot-third-party-policy.md): real-time prescriptive advice (level, roll, buy) is forbidden on every surface with no personal-tool exemption, so the opt-in mode risks the account; pre-game guides, comp-unit highlighting, stage-keyed leveling and post-game review are allowed; from 2026-10-06 Vanguard blocks memory access for unknown apps.
- [TFT stats data sources and their APIs](004-stats-data-sources-and-apis.md): only Riot has a documented API (match results, no positions or round-by-round econ); MetaTFT, tactics.tools and TFT Academy serve undocumented, unlicensed JSON; self-aggregation needs about 12.5k matches per patch for comp stats and far more for augments.
- [Prior art for TFT decision engines and the train-vs-LLM question](007-decision-engine-prior-art.md): no trained decision model is needed; a deterministic engine (rules, maths, statistics) leads, a local LLM (Vulkan only on the RX 6800) is at most a phrasing layer, and training belongs in screen-capture recognition if that route is chosen.
- [TFT econ, level and roll math and established theory](006-econ-level-roll-theory.md): odds, pool, XP, gold and damage numbers are published in Riot data and patch notes, and hit odds, the XP/gold calendar and level-versus-roll trade-offs are directly calculable; leveling lines and pivot reasoning are heuristics; board strength and pivot timing need statistics.
- [Policy stance and feature modes](008-policy-stance-and-modes.md): Live mode (advice from live state, all opponent data the route gives) is the product, on the main account at the owner's risk; Baseline mode is the same engine filtered to Guides, highlights and grey-zone hints; surfaces share the rules; post-game review joins v1; measured as 50 no-coach games, then 50 Live-mode games.
- [Data source strategy](010-data-source-strategy.md): MetaTFT JSON for statistics with tactics.tools as fallback, TFT Academy for Guides with an owner override file, Data Dragon and CommunityDragon for static data plus a hand-kept per-patch file; refreshed between games, never during one; Diamond+ filter; no Riot crawler in v1, and a personal key for the owner's own matches.
- [Advice engine architecture](011-advice-engine-architecture.md): a deterministic Engine, a pure function of snapshot and history, with a Game plan layer over per-decision sub-engines; optimizes expected placement, simulates Lines only for econ, level and roll, CPU only, no trained model and no LLM in v1; the Live advisor is the separable Live-mode part.
- [Transition and pivot domain model](012-transition-and-pivot-model.md): the Game plan is folded from history, Open then Committed with a Backup comp; comps are compared by comp fit (expected placement) summed from sub-engine fit terms; a pivot needs a per-stage margin and reverts if the player does not follow; transition is strength-gated with the roll-down as deadline; contest acts only through hit odds.
- [Register a Riot personal API key](017-register-riot-personal-api-key.md): personal key submitted and pending review; a 24-hour development key in `$HOME\.config\tft-assistant\riot-api-key` serves until then; app limit 20/s and 100/2 min; account, match, summoner and league endpoints all answer for the owner's EUNE account, which has 100+ matches.
- [Record the pre-coach baseline](016-record-pre-coach-baseline.md): rolling baseline of the last 50 no-coach ranked games from the same set as the Live-mode games, refreshed before the first Live-mode game; the 2026-10-04 snapshot is 4.62 average placement at Platinum III; the match API no longer reports the patch.
- [Econ, level and roll Line simulation](018-econ-level-roll-line-simulation.md): seeded Monte Carlo with common random numbers over about 7 candidate Lines to the end of the next stage; roll depth emerges from gold floors, with no HP table and no deliberate loss streak; a Line margin damps flips; the player can pin a Line in Live mode; the simulated placement is the backbone of comp fit for the target, Backup and top challengers, and other comps are screened analytically.
- [Board and lobby strength heuristic](019-board-and-lobby-strength-heuristic.md): board power is additive (per-unit-star power from tactics.tools star splits, trait breakpoints, generic items) with three global weights fitted on the owner's own matches; fight odds, placement, damage and the opponent growth curve derive from it; the comp classifier only labels; error is measured by final-board ranking now and fight logs later; no crawler added.
- [Item decisions](020-item-decisions.md): item value is the per-unit placement delta from MetaTFT item statistics, shrunk toward a class prior; item fit is the best assignment of items and components (at option value) to a comp's at most 3 item holders, relative to their usual items; slams are valued by a same-seed Line simulation pair; interim holders are units the comp will sell unless removers are held; Open plans weight items across candidates.
- [Augment decisions](021-augment-decisions.md): no Set 18 augment statistics exist (the match API dropped augments), so augment value is MetaTFT's per-comp, then global, curated tier mapped to a placement delta, with statistics switching on per augment if they return; augment fit sums held augments; econ augments use a same-seed Line simulation pair; reroll every option but the best; a comp-defining augment is one whose fit decides the top candidate; Baseline mode shows tiers instead of a statistics table.
- [Shop, Wisp and carousel decisions](023-shop-wisp-and-carousel-decisions.md): shop buys are analytic (key-unit copies, board power gain, pairs) within a gold allowance the Line owns; a bench priority order drives hold and sell calls; each Wisp's effect kind picks its valuation (simulation pair or choice rule plus a gold price), bought greedily over a margin; carousel is a ranked choice-rule list; no opener sub-engine; Baseline mode gets an offline per-patch Wisp worth table.
- [Probe live game data sources in a real TFT game](013-probe-live-game-data.md): port 2999 stays closed in-game and the League client API gives only the gameflow phase; borderless screen capture at 2560×1440 reads HUD, shop, Wisps, augments, carousel and scouted boards as text; the game can crash and restart mid-match; Wisps sit in every other shop counting rerolls, one per round, only at affordable prices; PvE ignores streaks; augment timers open at about 48–49 s; TFT Academy already overlays tiers and records games.
- [Game-state capture route](009-game-state-capture-route.md): screen capture only plus the League client API for game start, end and reconnect; OCR reads HUD, shop, Wisps, augments and traits; the board is read by purchase tracking plus a reused MIT vision model on the CPU if its benchmark passes; about 4 Hz change checks; stale fields silence their sub-engine; a game log with keyframes (or optional video) under a 20 GB cap; any aspect ratio, UI scale and locale.
- [Post-game review scope](015-post-game-review-scope.md): replaying the game log gives a replay record per decision point, shared by the review and a separate evaluation harness; cost is the Engine's expected placement delta judged without hindsight; top 5 moments plus full timeline, a game summary, what-if over scored options; shown advice is logged so ignored advice, capture gaps and Engine errors separate; match API adds final boards; no log, no review.
- [Benchmark open-source board recognition on probe frames](024-benchmark-board-recognition.md): TFT-COACH's board reader is adopted with fixes beside purchase tracking: every accepted own-board read and star level was right, items 171/177, 24 ms per CPU pass, but only 6 of 10 late-game units were read (a geometry bug and thin 5-cost training data); scouted boards give traits only in v1.
- [Positioning decisions](022-positioning-decisions.md): rule-based, never scored; a target layout from Guide hexes plus a histogram assignment for other units, adjusted for own hex mechanics, anti-dive and anti-AoE when the confidence-weighted share of possible next opponents with the threat tag crosses a hysteresis threshold; threat tags derived from CommunityDragon text with owner overrides; never a moment in review.
- [Stack and runtime](025-stack-and-runtime.md): a Python 3.14 core (capture, Engine, game log, review, harness) under an Electron, TypeScript and React shell that owns the overlay, second screen and voice, joined by a versioned JSON WebSocket; WGC window capture with the overlay excluded; digit templates plus RapidOCR; `live` as a separate package; JSONL game logs with a SQLite index; TOML hand-edited files; run from the repo with `uv`.
- [Advice surface UX](026-advice-surface-ux.md): a small overlay anchors advice to game elements and marks only opponents due a scout; the second screen is a cockpit showing everything at once; voice speaks only big moments plus scout lines tied to anti-dive or anti-AoE; Lines are pinned from the overlay chip or the second screen; paused advice becomes a grey dashed tag; roll-down mode reads the shop strip at about 15 Hz for buys and a tracker within 0.25 s; only the Line chip and the review toast take clicks.
- [Evaluation harness](027-evaluation-harness.md): the harness scores the Engine's predictions (fights, damage, hit odds, expected placement) against outcomes and diffs advice across versions, never gating on the 50-game placement; gates are "beat a naive baseline" and "no regression"; only fitted parameters are tuned on the owner's games, margins come from noise and are checked by flip rate, priors come from public statistics; refits only between 10-game blocks; silent games give logs early and count toward the pre-coach baseline.
- [Patch-day and new-set workflow](028-patch-day-and-new-set-workflow.md): a `new-patch` script copies the previous files, refreshes CommunityDragon and Data Dragon fields and writes a diff report, then an agent session fills the patch-note fields with a `source` tag on every field; tunables carry over except priors, which recompute; overrides carry over with stale ids flagged; a hand-kept EUNE patch calendar; Live mode runs on the previous static file until the new one lands; a new set gets a repair checklist and a per-set set-mechanic plug-in; the 50 Live-mode games finish within Set 18; board-reader crops are auto-labelled by purchase tracking.

## Not yet specified

- **Dedicated TFT client**: Riot's new PC client ships on 2026-10-09 or 2026-11-03. The screen-capture route needs re-checking once it is live (window title, HUD layout and the overlay anchors that follow it, LCU phases); `probe/probe.ps1` re-runs the client, port 2999 and capture checks.

## Out of scope

- **Input automation**: the coach never clicks, buys or moves units for the player.
- **LLM phrasing** ([Benchmark local LLM inference beside a live TFT game](014-benchmark-local-llm.md)): v1 phrases advice and review prose from templates, so no local language model runs; revisit after v1.
- **Overwolf** ([Game-state capture route](009-game-state-capture-route.md)): the owner does not apply for Overwolf developer access, which needs a manual approval; the coach reads the screen instead. Riot's April 2027 memory-access deadline may also affect GEP if its board data comes from memory.
- **Counter-positioning against opponent hexes and items** ([Positioning decisions](022-positioning-decisions.md)): placing against an enemy carry's hex or against Zephyr and Shroud needs opponent positions and items, which v1 does not read; scouted boards give traits only.
- **The next set's set mechanic** ([Patch-day and new-set workflow](028-patch-day-and-new-set-workflow.md)): v1 fixes only the plug-in contract and the repair order; designing the replacement for the Wisp sub-engine is a new-set effort once that set is known.
- **Public release and monetization**: a separate effort if the personal tool proves itself. This includes a real installer (electron-builder plus a frozen Python); v1 runs from the repo ([Stack and runtime](025-stack-and-runtime.md)).
