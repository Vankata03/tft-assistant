# Decision engine consumer contract

Ticket 41 implements the decision hooks used by `tft_engine.evaluate` and `advise`. These functions remain pure: snapshots, history and patch data are immutable inputs; review uses the same implementation as Live. Baseline and silent return before hooks or simulations. The underlying planning, ownership and phase requirements remain in [engine-contracts.md](engine-contracts.md).

## Snapshot observations

Every row below is a `fields` entry wrapped in `FieldValue(value, read_at, source, confidence)`. Reads, requirements and semantic seeds use `field_max_age_seconds`; raw timestamps remain in validity evidence. Completeness flags must be fresh literal booleans. Missing observations never mean empty inventories, zero counters or completed picks.

| Domain | Values and positive completeness evidence |
| --- | --- |
| Shop | `shop`: rows `{slot, unit_id, cost}`; complete typed `board`, `bench`, `inventory_complete`; gold and level. The selected Line supplies the spending boundary. |
| Items | `item_bench`: item IDs; `item_inventory_complete=True`; complete own ownership including equipped items. Item offers additionally require `choice_kind='item'`, `item_offers=[{slot,item_id}]` and `item_offers_complete=True`. |
| Augments | `augments`: exactly three `{slot,augment_id,reroll_available}` rows with literal boolean reroll flags; `augment_tier`; `augment_offers_complete=True`; `held_augments` IDs and `held_augments_complete=True` for valuation. |
| Wisp | `wisp={slot,wisp_id,cost}`, `wisp_complete=True`, `slot_count`, `wisp_purchases_this_round` as a nonnegative integer, and `wisp_purchase_count_complete=True`. |
| Carousel | `carousel=[{slot,unit_id,item_id}]`, `carousel_complete=True`; complete ownership and item inventory. Removed options are absent from the next positively complete observation. |
| Positioning | Complete own ownership, level and lobby; `board_settled_since` as a timezone-bearing ISO timestamp. Optional `position_locks` maps own unit index strings or IDs to cell indices. |
| Remaining effects | `remaining_effects=[{effect_id,source_kind,remaining_rounds?,remaining_rolls?,remaining_gold?,remaining_xp?}]` and `remaining_effects_complete=True`. Counters are observed nonnegative integers; `source_kind` is `augment`, `wisp` or `opening_encounter`. |

Choice valuation also needs fresh gold, HP, level, XP, streak and lobby. Registry `required_fields`, `fit_required_fields` and `dependency_fields` declare the fingerprints; internal completeness, model and counter checks can further suppress a dependent action. Activation fields avoid pausing an offer domain that was never observed. Missing economy inputs clear current fits and Lines while preserving the descriptive observed plan. An independent qualified augment tier table or base layout can remain visible.

Actual planning requires `phase` in `planning` or `roll_down` with `planning_phase=True`. Augment actions declare `augment`; carousel actions declare `carousel`. An item offer in augment phase also requires its explicit item-choice evidence. Choice snapshots project into hypothetical planning through `best_choice_fit`; they never fold as actual planning or publish projected econ actions. Combat, end, unknown, stale or inconsistent phase evidence cannot be promoted by changed fields.

Positioning excludes recent matchups only with `rules_flags.recent_opponent_exclusion_count`, an explicit nonnegative integer policy. No game constant is assumed. A positive count requires fresh `recent_opponent_fights_complete=True` and enough causal confirmed rows `{opponent_id,round_id,read_at}`. Rows retain fight-start timestamps and repeats; historical facts do not expire after two seconds. Identical facts repeated across snapshots are deduplicated by round, timestamp and opponent ID. Future observations cannot repair an earlier incomplete prefix. A missing rule or certificate pauses threat adjustments while permitting a sourced base layout.

Ticket 53 owns the producer integration for this certificate through persisted-prefix `project_fight_history(events,captured_at,round_types=...)` and the capture runtime handoff. Its producer requires a positively observed first sourced round and uninterrupted phase, round, opponent and HP evidence; gaps, restarts, intervals over two seconds or incomplete fights invalidate certification. Pinned round types separate player combat from PvE; unknown round types cannot certify history. A late attach cannot certify from a synthetic game-start event. Policy values and any alive-lobby reset rules still require patch qualification in ticket 48.

## Patch data consumed by decisions

All static/entity/tunable values retain the existing `TaggedValue` provenance. These are consumer shapes; synthetic tests do not establish production values or fitted parameters.

Items use entity `category` (`component`, `finished`, `tool`), `component`, and `item_class`; units use `item_class`. Tools have `tool_kind='remover'` or `'reforger'`. Item variants such as artifact, Radiant and support belong to the finished category and use their own item ID, statistics or qualified class prior. Guide `items` selects at most three holders; an unguided cluster can supply tagged `item_holders`. An owner Guide or owner holder override takes precedence. A unit's tagged `item_reference` is its expected usual-item benefit in placement units; otherwise qualified unit/item sample frequencies derive that reference. Missing class or reference support leaves the item term unavailable.

`rules_flags.item_slots_max` supplies capacity. `item_recipes` maps finished item ID to two component IDs. `reforge_pools` maps input item ID to explicit `{item_id,probability}` outcomes. `item_class_prior` maps unit class to item class to positive benefit in placement units; `item_prior_strength` controls shrinkage. `component_income_by_stage` maps stage to expected future component counts; `component_discount_by_stage` maps stage to a value in `[0,1]`. Neither missing stage nor missing component has a zero default. `slam_candidate_cap` caps only build/component tempo candidates, not finished-item or physical-handover options. Open allocation uses `open_candidate_temperature` and the current candidate fits.

Augment tiers come from immutable global `augment_tiers`, `comp_augment_tiers` keyed by cluster/comp, and Guide tags. `augment_tier_delta` also needs a qualified icon-tier prior for a new augment absent from tier lists. `augment_pick_rounds` maps round ID to canonical pick stage `1`, `2` or `3`. `Statistic.pick_stage` is optional and persisted; MetaTFT's zero-based `order` is explicitly converted to one-based stage. Invalid orders reject the source attempt. Refresh prior/deduplication keys include stage, so rows cannot inherit another pick's statistics. When a stage-specific row is absent, an aggregate row can be used explicitly; another pick stage cannot substitute.

Statistical augment valuation requires tagged `global_baseline_placement` on the augment entity and `statistics_min_samples=500`, matching `tft_data.config.STATISTICS_MIN_SAMPLES`. The baseline must describe the qualified global cohort, not an invented 4.5. Global rows below the existing 500-board policy retain the tier prior. A qualified comp baseline permits comp-specific shrinkage toward the global delta. Stale/changed flags multiply the prior by `augment_flag_prior_multiplier` and cap confidence. Tier-source publication before `filters.patch_start_at` marks stale tiers. An offer icon supplies a prior only for the newly projected pick; it cannot invent the tier of an older held augment. Unknown held-augment or item models suppress dependent choices while qualified static tiers remain visible. Source 51 preserves accepted provenance separately from rejected attempts; a failed fetch does not relabel retained rows as new evidence.

Positioning uses Guide/owner `positions` and `data.positioning[unit_id]`, a 28-cell histogram. `positioning_rules` is a sequence of `{unit_ids,cells,trait_id?,breakpoint?,augment_id?}` selectors. A trait rule requires authoritative own counts; an augment rule requires complete held augment IDs. `positioning_templates` contains `anti_dive={carry_cells,bodyguard_cells}` where bodyguard cells are keyed by carry cell string, and `anti_aoe={cells}`. Unit `position_role='backline'` and `item_class='tank'` identify template roles. Trait `threat_tags`, `breakpoints` and optional `threat_breakpoints` provide activation; refresh derives tags and preserves phrase/provenance evidence. No enemy hexes, items or inferred individual-unit positions are consumed.

`wisp_round_cap={default,trait_overrides}` uses tagged trait `wisp_cap_breakpoint` and authoritative own counts. `rules_flags.wisp_purchase_shop_slots_delta` is a nonnegative integer refill policy; `champion_slots_max` bounds the result. No refill value is guessed. `board_power_buy_min`, `wisp_buy_margin` and `comp_defining_margin` accept scalar values or stage maps, as do the existing Line/transition/pivot margin consumers. A missing stage leaves valuation unavailable; no stage-zero margin is invented.

## Effect encoding and accounting

`wisps`, `econ_augments` and `opening_encounters` map effect ID to `{effect_kind,values}`. Wisp entries additionally expose sourced `cost` and `offer_stages` for the offline table. Riot display categories never choose a valuation path.

| Kind | Supported values |
| --- | --- |
| `gold` | `gold`, `gold_per_round` |
| `xp` | `xp`, `xp_per_round` |
| `rolls` | `rolls`, `roll_cost_delta` |
| `shop` | `shop_slots_delta`, `roll_cost_delta` |
| `sale_modifier` | `sale_gold_by_cost_star` as cost → star → additional sale gold |
| `combat_buff` | `buff_id`, resolved by sourced `combat_buff_power` |
| `unit_grant` | `outcomes=[{probability,unit_ids}]` |
| `item_grant` | `outcomes=[{probability,item_ids}]` |
| `risky` | `outcomes=[{probability,effect:{effect_kind,values}}]` |
| `polymorph` | `eligible_costs`, `target`, `cost_delta`, literal `preserve_stars`, literal `preserve_items`, outcomes keyed by resulting cost containing `{unit_id,probability}` |
| `duplicator` | `eligible_costs`, `target`, `copy_star='one'` |

Recurring income and modifiers require sourced `duration_rounds` or explicit `scope='rest_of_game'` for a newly chosen effect. Captured effects require their observed remaining counters. Per-round `SimulationEffects.round_income` and `round_modifiers` expire on the sourced calendar. `target` is `uniform`, `highest_star` or `chosen`; highest-star ties require explicit `tie_policy='uniform'`, and a chosen target requires an unambiguous captured `target_unit_id`. Conditional probabilities must be finite, positive and sum to one. Unsupported fields, missing target/preservation rules or absent outcomes pause valuation.

Captured initial gold, XP and ownership are already in the snapshot and never applied again. Observed free-roll balances can enter the remaining state only for a matching sourced roll effect. Gold/XP counters without a payout-timing model remain unavailable. Held recurring econ augments must appear in a complete remaining-effect inventory. Projected new effects are marked with choice provenance and applied once. The simulator combines captured and explicit effects once; unchanged choices match direct Line simulation.

Simulation-pair Wisps pay their price within the pair; Risky prices are inside every conditional outcome. Unit/item grants use the choice expectation and a `rollouts_reroll` gold-price pair. Its paired error includes covariance for overlapping shared draws. A purchase also projects the sourced champion-slot refill. Wisp fit adds no curated value on top of effects already in Lines. Econ augment effects replace the tier contribution; item/unit/trait-grant augments use tier/statistics only, avoiding a second average grant valuation.

`compute_wisp_worth(data, standard_states)` returns an immutable patch table. The caller supplies stage-keyed complete snapshots with a locked Guide, sourced median HP and stage-average ownership. The Engine does not create those statistics. It evaluates the Guide Line or finite choice expectation, then labels `worth_it`, `situational` within two paired standard errors of the margin, or `skip`. `wisp_worth_overrides` maps Wisp ID → stage → owner label and wins. Missing standard states or models produce `unavailable` rows. A caller can install the qualified result as tagged `wisp_worth_table`; Live displays it only as low-confidence information when a model is unavailable. Baseline consumes the same current-stage row through additive `WispWorth.worth_label`, `worth_stage` and `paired_standard_error` fields, preserving the tag in `source`. Its cockpit and anchored overlay render a static stage label; missing or unavailable rows never fall back to another stage or an older numeric table. Existing flat numeric `wisp_worth` remains supported when no stage table exists. Silent mode clears both surfaces, and Baseline does not invoke the live pipeline. Producing current qualified standard states and wiring their patch artifact remains the source-preparation workflow, not proof supplied by synthetic tests. A stage-only reference price does not represent conditional free prices or round-gold eligibility gates; those source cases remain a ticket 48 qualification gap. Live always uses the positively captured current price.

## Values, identity and transport

`FitTerm.delta` and scored expected placements are lower-is-better. Item benefit, tempo gain and `placement_gain` are higher-is-better. Shop costs use gold; analytic shop options have no placement score. Positioning has neither placement nor standard error and contributes no comp-fit term. `ScoredOption.standard_error` for decision options is the paired difference error against the explicit hold, skip, defer or keep baseline, not a marginal Line error. Each raw `LineResult` retains its own marginal error and all rollout placements/deaths.

Shop priorities are analytic: target/Backup keys, owned pairs and sufficient board-power gains obey the Line's floor, then fixed bench priorities choose overflow/interest sales. Current component assignment searches consumption and holder capacity exactly. Future component option value uses independent Poisson partner arrivals derived from expected counts; this is an approximation, not a verified game distribution. Item fit assumes the best abstract inventory assignment. Physical advice separately respects equipped items on board and bench units, in-place recipes, sale returns, remover consumption and capacity. Its realized holder correction uses the same sourced placement benefit and removes positive overlap with abstract fit improvement. Generic rollout item power remains fixed as specified by the ticket 18 amendment; it does not claim that items physically transfer with future board swaps.

Reroll expectations retain every scored pool option, even when rerolling the best is rejected. `augment:keep` is the explicit baseline for that expectation. Conditional records preserve weights and chosen option IDs. Carousel advice ranks only the remaining captured options, using Guide priority for ties. Positioning uses exact maximum-log-frequency assignment, then own rules, anti-dive and anti-AoE with protected owner cells and at most one adjustment per unit. It reconstructs hysteresis and prior layouts from causal history, reissuing only for a board change or adjustment flip; voice fires only when a threat adjustment turns on.

Decision IDs use game, round, decision domain and a SHA-256 token of semantic dependency values plus data/model identity. Repeated fresh timestamps or snapshot nonces do not create new semantic decisions. Delivery revision remains the transport's responsibility. `validity_state` retains raw required/dependency `FieldValue` records, history, `data_snapshot_id` and `model_hash` so replay can establish the actual evidence prefix and candidate model.

Choice bundles preserve `before/after`, all `before_lines/after_lines`, plans and comp fits. `before_evidence_id` and `after_evidence_id` are content hashes: `sha256:` plus the hash of canonical JSON `{lines,plan,fits}` using sorted keys, compact separators and finite numeric values. `before_line_ref` and `after_line_ref` identify the selected comp ID, Line ID and seed within that bundle. Consumers can store each bundle once and transmit scored summaries with these references; replay must resolve the full evidence before claiming reproduction. Raw item tempo options expose their individual paired before/after Lines and physical inventory states; consumers can content-address those finite JSON records under the same canonical policy. The Engine does not drop candidates or distributions for transport.

Request-local simulation reuse keys complete stochastic inputs, effects, opponents, Lines, seed and data. It reuses fit-only projections without averaging or changing any rollout. `reuse_simulations=False` is a bounded parity/benchmark switch. `EngineEvaluation.workload` describes semantic scheduling; separate immutable `simulation_diagnostics` reports requests, cache hits, executed calls, concrete Lines and rollout-Line states. Diagnostic counters do not change result equality or option evidence.

## Verification limits

Public Engine-advice tests use synthetic tagged data and worked outcomes. They exercise analytic budgets, exact assignments, physical handover/tools, grants and price accounting, stage statistics, rerolls, disappearance ranking, phase/ownership/domain silence, history gaps, layouts and pairing. Data-refresh tests verify pick-stage rejection, persistence and prior isolation. These checks do not qualify current patch values, fitted owner-match parameters or recognition accuracy.

The reproducible synthetic benchmark is `core/packages/engine/tests/benchmark_engine.py --combat --augment-pool 21 --rollouts 64 --repeats 2 --result-json <path>`. It retains 65 units/Guides, 36 concrete candidate Lines and three reason Lines, with 64 rollouts, plus all three shown augment options and 18 unseen reroll outcomes. `--no-reuse` runs the paired comparison. Mac CPU timings and exact JSON hashes are recorded in ticket 41's operational evidence. Raw evidence can be large; 44/45 must use bounded summaries and resolvable references for UI transport. The 100 ms Ryzen/game-running target remains unmet in ticket 49. Current qualified source artifacts, Windows capture/live games and native teardown checks remain their respective integration gates.
