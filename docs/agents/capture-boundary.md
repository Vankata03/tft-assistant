## Running capture

Create `HudLayout.from_config(game_cfg_path)` to read `[HUD] GlobalScale` and `[General] WindowMode`. The fallback `HudLayout()` uses the committed 2560×1440 probe geometry and explicitly records `scale_source="probe-reference"`; it is not a successful calibration claim. Regions use fractions of the game client rectangle. Central, side and bottom anchors scale with client height and UI scale. `CapturePipeline(..., regions={name: (x0, y0, x1, y1)})` accepts explicit fractional calibration overrides.

Construct `CapturePipeline(game_id, ocr=reader, sink=session_store, layout=layout, catalog=catalog, visual_reader=vision, own_player_name=owner_name)`. Start the same game in `SessionStore` first. `CaptureRunner(WindowsCaptureSource(), pipeline).run(on_snapshot=callback)` belongs on a dedicated CPU thread. Call `stop()`, join that thread, and call `pipeline.close()` before ending the game log. The close call flushes media and terminal gaps; propagate its visible encoder failure to runtime status. Capture uses no input automation or process-memory access. The source rescans visible windows on each tick, rejects ambiguous or minimized windows, uses borderless WGC first, and falls back to a BitBlt client-area crop. Source changes, failed spans and replaced windows produce durable events. The caller must surface capture status from the log callback.

The callback receives JSON-compatible snapshots. `GameSnapshot.from_dict(snapshot)` restores the immutable Engine contract. Additional root metadata consists of `data_snapshot_id`, `phase`, `stale_fields`, `capture_layout`, `capture_copy` and `roll_down`. Use `CapturePipeline.from_data(game_id, data=pinned_snapshot, ...)` to project locale names, champion trait variants, observed effect-source identities and refund tables without patch guesses. When resuming, pass the original pinned data snapshot and the existing game events; a different data pin is rejected. Each observed field has `value`, a timezone-bearing ISO `read_at`, `source` and `confidence`. Snapshot IDs include a capture-instance nonce so restarting capture in the same game cannot collide with old IDs. Failed frames or reads retain original values and timestamps. Successfully captured unchanged regions advance `read_at` while retaining recognition provenance and confidence. Missing values remain missing.

Normal change checks request a 250 ms interval. Two confirmed paid rolls within two seconds, or `pipeline.start_roll_down(gold_floor=..., timestamp=...)`, request a 1/15 second interval for shop and gold between normal checks. Other regions retain their regular checks. Roll-down ends after three seconds without a confirmed roll or a freshly read gold floor. The runner subtracts processing time from the wait; this scheduling policy does not prove the Windows latency budget. The lifecycle owner calls `finish_calibration_round()` after the first round, including a round with no readable HUD. It records an actionable `calibration_status` when nothing was read. That hook requires runtime wiring in ticket 45.

## OCR adapters

`TextLine(text, confidence, box)` uses a normalized `(x0, y0, x1, y1)` box within its OCR crop. `NameCatalog` accepts `{kind: {entity_id: localized_name}}` for units, traits and Wisps. Supply the pinned client-locale names from the data snapshot. Unknown or closely competing matches return no identity.

`DigitTemplates.from_directory(path)` requires calibrated `0.png` through `9.png`, `minus.png` and `slash.png`. Genuine game-font assets remain to be prepared; the synthetic glyph test establishes matcher behavior only. `RapidOCRReader` requires explicit local detector and recognizer models, plus a dictionary when the recognizer does not embed one. `from_bundled_models()` selects the verified small ONNX models shipped in RapidOCR 3.9.2. All execution providers are CPU-only. `WindowsOCRReader(locale)` requires the installed Windows language pack. Its confidence is a configured policy value because Windows OCR provides no scores. `HybridOCR(digits, names, fallback=...)` selects numeric templates before text OCR and records the actual selected source. No adapter downloads assets during capture.

## Visual reader contract

The public protocol is `tft_capture.vision.VisualReader`. Implement:

```python
read(image: PIL.Image.Image, *,
     regions: dict[str, tuple[int, int, int, int]],
     own_view: bool | None) -> VisionRead
```

`image` is an RGB PIL image or an owned `RegionFrame` of the current game client. Readers can borrow `image.bgr_view()` when available; OCR and template readers use its PIL-compatible `crop()` method. Pixel regions are `(left, top, right, bottom)` within that image; right and bottom are exclusive. Standard region names are `board`, `cards`, `shop`, `traits`, `players`, `scouted` and the numeric HUD names. Explicit calibration can add `bench` and `carousel`. During fast shop sampling the region map can contain only `shop` and `gold`. Readers must not emit fields from absent regions. The pipeline avoids repeated visual reads when its supplied visual regions and own-view state are unchanged; a reader may also cache individual changed regions internally.

`own_view=True` requires the owner name to match a label successfully read or confirmed on this same frame. `False` means another player is positively identified. `None` means identity is unavailable. The pipeline updates identity before invoking the reader and rejects own board, bench and inventory values unless `own_view=True`. The reader must never emit opponent units, items, stars or positions. Trait sightings are captured separately and require a known owner identity and a freshly confirmed opponent label, level, round, trait rows and hidden-row count.

Return `VisionRead(fields, source, confidence, inventory_complete=False, provenance={})`. Optional per-field provenance maps observed field names to `{source, confidence}`; the pipeline preserves it when unchanged pixels confirm freshness. Every supplied field must be a positively observed JSON value. An absent key means unreadable; an empty list means positively observed empty. An unreadable result must omit that field rather than repeat its previous value. Exceptions and empty results stay retryable without advancing timestamps. `confidence` is between zero and one. `inventory_complete` requests independent ownership validation; it does not authorize a complete snapshot by itself. It is false by default and must remain false for partial observations. The pinned `BoardReader` always returns false: known late-game misses prevent it from certifying exhaustive ownership alone. The full capture certificate below also requires calibrated exhaustive slots, a current unit count and complete current own traits.

The existing own board shape is:

```json
{"board":{"units":[{"unit_id":"shen","stars":1,"items":[],"position":0}],
          "bench":[],"trait_counts":null}}
```

A separate `bench` field, if supplied, is a list of the same unit objects. `position=null` represents unknown position. Missing equipped item identities must not be claimed as an empty item list unless emptiness was observed. Complete reader reconciliation uses the independent certificate below; partial observations remain available without authorizing ownership advice.

`shop_empty_slots` is a list of zero-based positions in the five-slot shop strip. Supply it only when a slot is positively observed empty. Failed name OCR alone is insufficient. The pipeline combines this evidence with same-round shop transitions and a matching gold delta to log a unique purchase. A gold delta alone, multiple empty slots or conflicting evidence cannot establish a unique purchase. An unobserved shop interval beyond two seconds (0.5 seconds in roll-down) records ambiguity rather than attributing a purchase. The tracker records confirmed acquisitions, not a complete initial inventory. Reader reconciliation and full ownership tracking retain these distinctions when logging sells, grants and copy totals.

A positively observed `planning_phase` boolean can also be returned; capture never defaults an unread phase to planning. Carousel and augment/choice fields can be returned independently of `own_view`. Their agreed entity shapes and completeness flags are listed below. OCR cannot identify 3D carousel units or equipped item icons.

## Offline crop and training commands

Run these commands from `core/`; use a new candidate directory for each training run:

```text
uv run tft-train crops --log <game/events.jsonl> --output <crop-directory>
uv run tft-train split --dataset <crop-directory/crops.json> --output <split.json>
uv run --group train tft-train train --current <current-model-directory> --split <split.json> --output <candidate-directory>
uv run tft-train compare --current <current-model-directory> --candidate <candidate-directory> --split <split.json> --report <report.json>
uv run tft-train accept --current <current-model-directory> --candidate <candidate-directory> --split <split.json> --report <report.json> --pointer packages/capture/src/tft_capture/models.json --cache <models-directory>
uv run tft-train calibrate --samples <reviewed-foot-samples.json> --output <foot-offsets.json>
```

Crop harvesting pairs a keyframe only with a board read at its exact timestamp. Labels require complete independent ownership and matching copy counts. A unique remaining identity can label the final unread crop and derive its stars from one, three or nine copies. Ambiguous crops remain unlabelled. Every crop records its game, keyframe, image hash, bounds, label source and reader version. Reviewed foot samples include `champion`, `bar=[x,y,width,height]`, `foot_y`, `source` and `game_id`; calibration records per-champion medians and sample counts.

The split keeps whole games together and groups games sharing identical crop bytes. It verifies image hashes, game separation and split fingerprints. The classifier reconstructs the actual current EfficientNet-B0 parameters from ONNX, including folded normalization, and checks initial logit parity before training. Fine-tuning and ONNX export run on CPU. Export parity must pass before the complete candidate bundle is published. The candidate retains every current class; training does not change the accepted pointer.

Comparison evaluates current and candidate on the same immutable held-out split and deduplicates identical pixels. Every current class needs at least 20 distinct labelled crops across five held-out games. Reports include exact counts, per-class correct predictions, descriptive Wilson intervals and paired whole-game regression probabilities. Absent classes are unqualified. Acceptance requires retained label coverage, qualified ownership/review labels, candidate overall accuracy at least equal to current, and no class regression beyond the one-sided 0.05 paired-game threshold. This gate qualifies the unit classifier; candidate star weights and metadata must remain identical to current until a separate star gate exists. Promotion reruns comparison rather than trusting an edited report and verifies and caches all six files before atomically replacing the portable pointer. It hashes both bundles before inference and checks those hashes after comparison and copying and before pointer publication. A rejected candidate leaves the last-good pointer unchanged and removes any new cache version created by that attempt. Commit a changed pointer only after reviewing its report; weights remain outside Git.

## Confirmed events and recovery

Copy transitions require two complete independent same-round inventories. Purchases use a unique changed shop slot and matching cost. A sell requires a one-, three- or nine-copy loss, planning evidence and the exact pinned star-level refund. An unexplained gain or loss produces `tracking_ambiguity` with a keyframe. A positive grant receipt identifies its source, unit and copy count; it confirms a Wisp, encounter or duplicator grant only when the independent gain matches exactly. A repeated receipt cannot explain a later gain.

`augment_pick`, `item_pick` and `carousel_pick` require a positive pick notification referencing a recent complete offer. A unique newly held augment following two complete held reads can also confirm a pick. Offers disappearing alone prove nothing. Choice tokens prevent repeated notifications from adding another pick. A pick notification and the same newly held augment do not add two copies of the held ID. Carousel events record whether the acquisition is already included in an independently observed ownership gain; pending or ambiguous overlap disables complete ownership until another independent read. Recovery preserves the acquisition lower bound without inventing its position or equipped items. Changed augment IDs paired with an observed true-to-false reroll transition produce per-option `augment_reroll` events.

A fresh combat phase, opponent identity, round and HP establish `fight_start`. A positive victory/defeat/draw read and current HP in that same round establish `fight_result` and `last_fight`; HP loss is recorded only when the measured after-HP does not exceed before-HP. Planning or the next round cannot infer an outcome. Missing outcomes produce `fight_incomplete`. Confirmed starts also retain `recent_opponents` and timestamped `{opponent_id, round_id, read_at}` rows in `recent_opponent_fights`.

`level_up` requires successive complete fresh level/XP reads with an increased level and no intervening gap. It records before/after level, XP and XP-to-level, both read timestamps, sources and confidence. A gold drop never attributes an XP purchase. Until direct XP-action evidence exists, capture does not emit an XP-buy event.

Resuming with the same game's events restores last-known field values with their original timestamps, ownership lower bounds, choice deduplication and an unfinished fight. It does not make historical observations fresh or reestablish missed transition continuity. Capture-instance snapshot IDs remain unique. Runtime must supply the original pinned data snapshot; refreshing data cannot change a running game's capture pin.

## Region copies and media lifecycle

`RegionFrame` retains the native NumPy surface and any explicit owner until consumption. The locked Windows Capture 2.0.1 source builds NumPy views through a ctypes exporter that retains `NativeMappedFrame`; this supports borrowing the buffer after the callback returns. The checked [2.0.1 source distribution](https://files.pythonhosted.org/packages/85/00/326a51bc2b27bc53e2a3e6d0c8f320af7e65f8315fb0d1d149699ca45995/windows_capture-2.0.1.tar.gz) has SHA-256 `2c2b394f4587b067cf520456f7f64c11b00380851b077a4d061fe5356a9a7645`. This is source evidence; actual Windows mapped-buffer lifetime remains a device check.

WGC polling no longer converts the whole surface to RGB. BitBlt transfers into an owned top-down 32-bit BGRA DIB, flushes GDI before reading and releases the bitmap when its frame owner is released. Requested rectangles make cached RGB crop copies. The board reader borrows BGR pixels; full RGB materialization occurs once only when a keyframe or full-video frame needs it. Snapshot `capture_copy` reports `region_rgb_bytes`, `region_rgb_copies`, `full_rgb_bytes` and `full_rgb_copies`. A full native capture surface and GPU readback still exist; this optimization removes the unconditional Python full-RGB copy. Pixel transforms retain the client rectangle's physical size and exclusive right/bottom coordinates.

Keyframes remain lossless through `SessionStore.write_keyframe`. In `full_video` mode, supply `SegmentRecorder(session_store, executable=ffmpeg_path)` and set the store's media mode before sampling. Its bounded background queue encodes timestamped variable-rate H.264 MP4 segments and writes `video_segment` events with original frame timestamps. Queue overflow produces `video_gap`; a missing or failed encoder produces visible `media_status=unavailable`. Silent keyframe mode does not create video frames.

On window loss or replacement, capture invalidates tracking continuity and flushes the video segment. `pipeline.close()` flushes the final segment, records a terminal capture gap and any unfinished fight, then records `capture_closed`. It is idempotent. Encoder failure still records closure and is raised to the lifecycle owner. Queue flush is nonblocking and reports overflow. Close has a configurable deadline (30 seconds by default, five seconds in the supervised runtime). A deadline stops the recorder’s own encoder subprocess and reports incomplete media; encoding also retains its 30-second per-segment subprocess timeout. Runtime must stop and join capture, close the pipeline, handle its status/error, and only then call `SessionStore.end_game`. FFmpeg availability and distribution require runtime packaging; software codec tests do not establish target-device performance.
