# Engine contract pointers

Ticket 39 owns the shared contracts and board/opponent functions. Ticket 40 owns the complete `advise(snapshot, history, data, mode)` pipeline. Imports for Baseline features must come from `tft_engine.allowlist` only.

## Snapshot and log shape

`GameSnapshot(game_id, round_id, captured_at, fields, snapshot_id='')` contains an immutable mapping of `FieldValue(value, read_at, source, confidence=1.0)`. Timestamps must have a timezone. `snapshot.field(name, now=..., max_age_seconds=...)` returns the value or `None` when it is missing or stale. Engine callers pass the shared field-age tunable; the convenience default is two seconds.

A `Board` contains `units`, `bench` and optional authoritative `trait_counts`. Each own `Unit` has `unit_id`, `stars`, equipped item IDs and an optional `position`. Duplicate units contribute power separately but contribute their traits once. Variable grants require authoritative counts or a sourced rule that resolves the active form.

A `TraitSighting` contains only `opponent_id`, `round_id`, `level`, `traits`, `hidden_traits` and optional `read_at`. It cannot encode opponent units, stars, positions or items. `GameHistory` contains snapshots and sightings. Every public log contract exposes `to_dict()` and `from_dict()`; their output is JSON-compatible. Snapshot decoding restores typed own boards and benches, and freezes other JSON fields.

`Advice` contains the required decision, action, urgency, confidence, reason template, numbers and validity. It also carries stable decision and option IDs, a structured payload, scored `ScoredOption` records, anchors and validity-state values. Scored options preserve expected placement and its standard error when applicable; positioning can leave these absent. `rank_advice` ranks urgency before placement impact. Surfaces do not re-rank it.

## Board and opponent functions

The public functions take a `DataSnapshot` explicitly. `strength(board, level, data)` returns a number; `estimate_strength` also returns confidence, the three weighted terms and warnings. `win_probability`, `placement` and `surviving_units` implement the specified combat projections. `placement` receives aligned opponent power and HP sequences and the stage damage divisor. `surviving_units` receives the winner's unit count.

`classify(board_or_marginals, data, limit=...)` returns normalized similarities and labels. Own bench presence is weighted once and cannot double-count a unit on the board. `infer_opponent(sighting, data, previous=...)` returns marginal unit probabilities, top-set certainty and the exact candidate count. `estimate_opponent` adds expected power, the advanced level, fading expected pool copies, labels and confidence. `opponents_from_history` folds sightings chronologically without hidden state.

Opponent confidence is age weight multiplied by inference certainty and data confidence. Trait-only threat consumers use the age weight. Never-seen or unsupported opponents use the par growth curve with no inferred pool reduction.

## Data additions

The Engine requires `level_calendar` (round to standard level), `stage_items` (stage to `finished`, `component`, `high_cost_finished`) and the lobby top-4 rate. `opponent_star_mix` is round to cost to three probabilities. `cost_star_baseline` is cost to star to prior power. `size_level_prior` is level to distinct-unit count to probability; `emblem_count_prior` is count to probability. Item values use `finished`, `component` and `high_cost_bonus`; classifier weights use `carry`, `key`, `other` and `bench`.

Trait entities expose `values.breakpoints`. Rich statistics expose unit-star or trait-breakpoint top-4 rates and sample counts, plus public unit play rates. Explicit tagged entity values named `top4_rate_<star-or-breakpoint>`, `sample_count_<star-or-breakpoint>` and `play_rate` are also supported. Average placement is never a substitute for a top-4 rate. Missing unit splits use the configured cost-star prior with lower confidence. Missing required game tables raise `DataError`.

Unit power uses a binomial prior centered on the cost-star power transformed back to a top-4 rate. Trait power uses a separate `trait_prior_strength` centered on the lobby rate. Shrinkage occurs before the logit, which makes thin 0% and 100% rows finite without an invented epsilon. Endpoint rows without sample counts or positive prior strength are unavailable. Unsampled interior tagged trait rates remain usable as explicit values.

`trait_rules` is keyed by unit ID. `replace` lists complete trait-count variants. Otherwise `counts` overrides base trait counts, `choose_one` lists additive alternatives and `optional_traits` allows any subset. This represents Lux's chosen origin, Elder Dragon's doubled grant and Kha'Zix's evolution subsets without set-specific logic in code.

`growth_curve(data, observations=...)` returns an immutable computed table. A refresh caller can pass it as the `opponent_growth_curve` computation hook. Optional observations are `(round_id, power, confidence)` triples and produce a stage correction. `growth_curve_lookup` uses that table when present and computes missing rounds from the calendar, shop odds, star mix and generic items. Refresh recomputation ignores the carried table.

Independent shop types have `kind='unit'`. NPCs and `unit_form` rows do not create additional pool types. Forms use tagged `pool_id` and `canonical_id`; owned and Guide forms preserve their active traits and prefer their own sampled power rows. Lux's complete sourced variants grant Avatar once and the chosen origin twice. A purchase, owned-copy count or key goal uses the shared base pool. An unresolved base form needed on the owned or target board is explicitly unavailable.

Opponent inference uses symbolic dynamic programming over feasible trait-count vectors. Each distinct unit set receives one prior weight even when multiple form assignments produce the same counts. `opponent_inference_state_cap` bounds the number of symbolic states. Exhaustion returns no marginal probabilities or copies, zero certainty and candidate count, and a visible fallback reason. The opponent estimate then uses par growth at zero confidence. Retained support is empty; omitted support is unenumerated. It never presents a partial posterior as exact.

## Planning and decision hooks

`advise(snapshot, history, data, mode, hooks=None)` returns ranked immutable advice. `evaluate` returns the same advice plus `GamePlan`, every screened or simulated `CompFit`, all scored `LineResult` records, the recommended board and current workload counts. Baseline and silent modes return before planning, simulation, opponent inference or hooks. Review runs the Live pipeline offline.

History is folded deterministically over earlier planning snapshots from the same game. Each step consumes only its earlier history prefix and sightings available then. `GamePlan.to_dict()` exposes Open or Committed status, target, Backup, candidate IDs, selected Line, pivot/rejected-pivot state and player divergence. Commitment, stage-dependent pivot margins, line hysteresis, picker locks and ignored-pivot adoption use the shared tunables. The target simulation is reconciled with the current Backup because protected Backup units affect sale gold. A repeated target/Backup cycle pauses econ explicitly.

`DomainHook(name, required_fields, fit=None, advice=None, fit_required_fields=(), advice_phases=('planning', 'roll_down'))` is the decision extension boundary for ticket 41. `fit(comp_id, context)` returns `FitTerm(delta, reason, numbers={}, confidence=1)`; negative placement deltas improve fit. `advice(context)` returns advice records. `EngineContext` provides immutable snapshot, history, data, plan, fits, Lines, recommended board, seed, opponents and workload. `best_choice_fit(context, changes, hooks=None)` evaluates changed fields with the original seed and fit-only hooks, preventing recursive choice advice.

Choice evaluation folds the same observed history, retaining its target/Backup, line hysteresis and pins through the ordinary planning rules. Its score is the best simulated candidate fit. When current simulation is unavailable, it returns `None` and clears preserved earlier fits/Lines, so a caller cannot price a choice from stale results. The returned evaluation carries the paused-domain reason. Gold counterfactuals are checked against direct same-seed simulations, including the equivalent `SimulationEffects.gold_delta` pair.

Missing or stale fields pause the dependent domain in place. Missing econ fields preserve the folded plan and still run hooks whose own requirements are satisfied. The econ input fields are `board`, `bench`, `gold`, `hp`, `level`, `xp`, signed `streak` and `lobby`. Lobby HP entries are sorted by ID; `player_id`, `local_player_id` or `is_self` identifies the local entry, and nonpositive opponent HP excludes eliminated players. Current `shop` accepts unit IDs or records with `unit_id`, optional captured `cost`, and slot metadata. Fresh captured offers are deterministic; unread offers do not become fabricated current shops.

Actual planning and history folds require fresh `fields.phase` equal to `planning` or `roll_down` and fresh literal `planning_phase=True`. Capture publishes literal False for `augment`, `carousel`, `combat` and `end`; contradictory, missing, stale, unknown or nonboolean evidence never enables actions. Nonplanning snapshots preserve the last observed plan but clear current fits, Lines and the recommended board. Hook actions require a declared `advice_phases` entry; combat, end and unknown phases permit information only. Augment and carousel hooks can declare their own choice phase. `best_choice_fit` validates the original phase before changes, then projects a known augment/carousel choice into hypothetical planning using the original seed and fit-only hooks. Its returned plan and advice belong to that projection; callers publish the choice advice, not projected econ or transition actions. The observed context and plan remain unchanged, and observed choice/combat snapshots never enter planning folds. Changed fields cannot promote unknown, combat or end evidence. Item choice hooks must also validate `choice_kind` and captured item offers; no item choice is inferred from phase alone. Timestamped phase evidence survives JSON decoding in `fields.phase`; the capture snapshot's top-level phase is a convenience value.

Ownership-dependent consumers also require a fresh literal `inventory_complete=True`. Capture certifies the complete board and all nine bench slots, including unit identities, stars and equipped items, and publishes typed board, bench, owned copies and this certificate together. A partial typed board remains an observation; its omitted units are unknown. Requirements containing `board`, `bench`, `owned_copies` or `slot_inventory` automatically include the certificate. False, missing, stale or nonboolean certificates pause plan, Line, transition and dependent hook valuation. Incomplete history entries do not contribute fits. Current fits, Lines and the recommended board are cleared while the last complete descriptive plan remains available. Independent hooks can still present fresh observations, but `best_choice_fit` returns no score and cannot promote an incomplete original inventory through changed fields. Direct `simulate_lines` calls reject unavailable ownership with `DataError`.

The strongest-owned-board transition uses greedy selection with strict swap improvement. Comp progress breaks near-power ties and the Guide's main roll-down deadline forces comp membership. Swap, Hold and Sell payloads identify units and the recommended board. Holds and overflow/roll sales use the shared `bench_priority` contract. Item handover and positioning remain decision hooks.

## Line simulation and effects

`Line(id, levels={}, rolls={}, stabilize=False, floor_options=(), family_id=None)` has JSON helpers. `candidate_lines` preserves Guide, early/late level, roll-now, roll-next, hold and emergency stabilization families when applicable. `line_candidate_cap` caps schedule families before expanding every `gold_floors` choice. Widened-candidate harness checks must widen both. A pin should contain a validated Line mapping, so it survives comp changes; an unavailable string-only pin pauses explicitly.

`simulate_lines(snapshot, history, data, comp_id, lines, effects=None, rollouts=None, opponents=(), seed=None, backup_id=None)` scores every concrete Line to the end of the next stage. `LineResult` preserves expected placement, standard error, death and hit probabilities, all projections, individual rollout placements/deaths, confidence and seed. Projection gold is after income; `planned_gold` is before income and is the shop budget boundary. Econ advice exposes every scored option, projections, plan, selected floor, sale list, pin alternative/gap and workload.

The seed is SHA-256 over canonical snapshot JSON. Shop draws are addressed by round and refresh; paired choices keep their draws even when gold, XP or shop count changes. Dense NumPy arrays batch Line × rollout states. Cached unique copy/level states use greedy selection followed by strict swap improvement; the deadline forces carry/key/other membership before filling remaining slots. Request-local board memoization preserves the full Monte Carlo distribution. `paired_value` returns placement gain, paired standard error and all before/after results. Stabilization ignores target-hit stopping and buys immediate board-power improvements, including completed interim pairs.

`SimulationEffects` carries an alternative own `item_state`, one-round power, initial gold/XP, cost, free rolls, recurring gold/XP, roll-cost and shop-slot deltas. Choice hooks translate sourced Wisp, item and econ-augment effects into these values. Effects already reflected in captured gold or XP must not be applied twice. Remaining grants require a captured remaining state or an explicit counterfactual effect. There is no hardcoded opening encounter or augment math in the simulator.

Rollouts intentionally keep the initial generic equipped-item term fixed across Lines and future subsets, including its initial high-cost-carrier bonus. This is the explicit amendment in `issues/018-econ-level-roll-line-simulation.md`, comments dated 2026-10-04, and the terminal/item-state contract in `docs/spec/sub-engines.md`. A changed `item_state` changes that generic term in a same-seed pair. The current-board transition instead counts equipment on its selected units and never invents a physical transfer. The generic rollout assumption does not prove that an item stays equipped after a bench swap; actual sale/remover/handover advice belongs to the item hook. Item fit remains a separate comp term.

Economy uses sourced XP purchases, passive XP, base income, interest, streaks, PvE streak preservation/orbs, sale values, shop odds and pools. Captured living opponents remain in rollout fights; their future eliminations and purchases are not invented. Dead players stop buying, earning income and receiving passive XP. At death, expected elimination rank reuses the placement HP/power coefficients against captured opponent HP and projected power, then remains frozen. Surviving terminal states subtract `terminal_gold_weight × held gold` as an approximation to buying capacity beyond the horizon, clamped to valid placement bounds. These coefficients remain default or carried, with capped confidence, until fitted by ticket 42.

Simulated comp fit uses the best Line placement plus domain fit; owned progress, hit odds and feasibility are not added twice. Its reason-only key-arrival counterfactual grants missing key copies without cost at the main roll-down. It explains missing-key placement cost and never chooses or prices an action. Death reason cost is the observed probability times the dead/surviving conditional placement gap; it is unavailable when every rollout dies. Analytic shop odds are a cheap conditional helper; they do not replace simulated variance.

The simulator requires canonical `round_order`, `round_types`, `xp_table`, `gold_by_round`, `streak_gold`, `interest`, `player_damage`, `rules_flags`, `shop_odds`, `pool_sizes`, `sell_values`, `bench_size`, `level_calendar`, `stage_items` and `trait_rules` tables. Guide defaults accept `{line: [points]}` or `{roll_level: level}` by carry cost; the latter uses the first sourced calendar point reaching that level and the highest configured floor. Missing required data pauses rather than inventing game constants.

Ticket 41's snapshot, effect, source, pairing and transport schemas are documented in [decision-contracts.md](decision-contracts.md). Default hooks implement shop, item, augment, Wisp, carousel and positioning decisions.

## Evidence limits

Tests use synthetic public-boundary fixtures. They cover exact posterior sets, hidden inactive rows, emblem slack, special grants, fading sightings, finite endpoints, JSON replay, planning/history, domain pauses, transitions and Line economics. A bounded subprocess checks an ambiguous 215,553,195-set case. Batched results match individual Line results exactly with combat, death, floors and effects; zero-effect pairs have zero gain and paired error.

`core/packages/engine/tests/benchmark_engine.py` reproduces the bounded Mac CPU workload: 65 synthetic independent units, 65 Guides, 3 simulated comps, 12 concrete Lines per comp and 64 rollouts per Line, plus 3 reason counterfactual Lines. Workload reports actual passes and expanded simulations, including Backup reconciliation when required. The sourced roster smoke separately checks 65 independent unit types and 9 Lux forms against the cached CDragon roster; public-statistic priors remain synthetic. Neither fixture qualifies fitted parameters or gameplay accuracy.

Mac timings exceed 100 ms. Target Ryzen 7 7800X3D/game-running qualification and any further required optimization remain ticket 49. Windows capture, held-out recognition accuracy, ranked games and fitted owner-match parameters have not been verified by these package tests. Ticket 48 owns current patch provenance and candidate completeness.
