# Source publication and qualification

`HTTPSource.metadata()` describes the response from its own `url`. Its `updated_at`, patch label, Set and queue identity, editorial timestamps, raw filters and revision come from that response. The optional `metadata_url` is a donor hint: its patch, update timestamp and revision are recorded in `donor_hint` and never qualify the primary payload. A missing donor cannot invalidate otherwise qualified primary metadata.

`SourceMetadata.patch` is `None` when the payload provides no patch. `cohort` records `minimum_rank` and `regions`, with `None` for unknown values. `SourceConfiguration` applies the configured statistical goals to every statistics source, including the fallback. Query parameters and expected raw filters express requests; they do not establish that a response represents Diamond+ or all regions. Provider enum values remain in `filters`; the adapter does not infer cohort names from unchecked enum mappings. Thus a raw `rankGroup=1` check alone does not qualify an all-region statistical cohort.

Refresh rejects unqualified payloads before parsing or installing their advice data. It keeps a qualified last-good value with a warning, or leaves that source unavailable. Previously cached rows without evidence for newly requested cohort requirements are removed from the new snapshot. Legacy source records without qualification metadata require requalification; historical snapshot directories remain unchanged. `MemorySource` uses payload-owned publication metadata when present, so its fixture envelope cannot supply a patch for an unlabelled cached response.

`SourceState` stores the accepted publication, fetch time and qualification evidence. A rejected newer publication is stored separately under `last_attempt`, including its reason and observed metadata. Retention never advances the accepted timestamps. These fields, warnings and donor hints survive immutable snapshot persistence and reload. Statistics and enrichment retain their one-hour refresh age; Guides retain six hours. Fallback rows belong to the fallback source and follow its own age.

The `tft-data refresh` CLI prints qualification and stale-data warnings. A zero exit means that a validated immutable snapshot was produced; it does not certify that every external source was available. Check the snapshot's warnings and source qualification before claiming source readiness. `config.STATISTICS_MIN_SAMPLES=500` names the existing thin-sample application policy; it is not a provider-observed sample threshold or a fit.

Ticket 51 verifies this software boundary using external-service fixtures and checked response shapes. Ticket 48 still owns current-patch source coverage, static tables, cohort qualification and fitted parameters. No production candidate or owner API call is part of this verification.
