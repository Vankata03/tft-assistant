# Historical replay and review access

`tft_review.ReplayProducer(sessions, data_store, repository=checkout, hooks=None, hook_version="default").produce(game_id)` consumes a real SessionStore log. It restores the exact immutable DataStore snapshot pinned by `game_start` and calls the shared Engine in `review` mode. It does not refresh historical data, import Live or implement separate decision math. An explicit hook tuple uses the Engine's existing DomainHook interface; `None` uses its default registry. Callers must version any external configuration used by their hooks through `hook_version`. Stateful closures and opaque callable objects are evaluated but cannot reuse a cache.

The returned ReplayBatch contains frozen ReplayContext and ReplayRecord tuples, the original observation ledger and a versioned identity. Their `to_dict()` and `from_dict()` methods preserve finite JSON values. Contexts retain the original snapshot, including capture metadata, field timestamps and sources, game-start metadata, authoritative log sequence, actual evaluation seed and the complete EngineEvaluation result. Engine decision IDs remain separate from snapshot IDs. Identical polling snapshots remain separate contexts so ticket 42 can reconstruct decision boundaries without losing evidence.

`batch.history_for(context)` rebuilds only snapshots and trait sightings with earlier log sequences and timestamps no later than the context's capture. The sighting event's timestamp is authoritative. A known recovered gap resets the causal history only after both its log sequence and availability time enter that prefix. Later snapshots, outcomes and gap annotations cannot alter the earlier Engine information prefix.

Capture gaps also serve as retrospective validity annotations. A later crash annotation can identify invalid capture evidence in an earlier interval. Such contexts retain the original snapshot and explicit `validity_annotations`, including the gap's sequence, timestamp and whether it is retrospective. They have no evaluation or advice records. This exclusion does not supply later game facts to the Engine. Gap intervals include their start and exclude their end. An opening recovery gap with an unknown start remains explicit. Stale fields keep their original reads; the Engine applies its own field-age requirements, and the context also preserves recorded stale-field reasons.

Records retain the Engine's scored options and selected expected placement when that domain provides one. Observed player choice, signed cost, paired uncertainty and shown attribution remain `None` with unavailable reasons. Positioning stays available as a non-costed domain. Ticket 42 owns policy reconstruction, frozen candidate valuation, grouping, costs, display matching, metrics, fits and CLIs.

Cache identity includes the actual Git commit, relevant tracked and untracked changes, hashes of the running data/Engine/review sources, historical data and tunables, the non-cache log, schema, hook registry and recorded reader version. The supplied checkout must match the running package sources for clean reuse. Only unchanged, finished logs with clean sources and cacheable hooks reuse output. Active or dirty games can produce records but do not read or publish reusable caches. Inputs are checked again after evaluation and cache reads; publication checks the log under the SessionStore lock. Cache provenance is excluded from observations and the log fingerprint. Cached bytes are checked against their logged content hash. Missing or corrupt data, malformed committed evidence and changed inputs fail visibly.

`ReviewAccess(sessions).publish(batch)` stores replay content without unlocking it. `read(game_id)`, `read_batch(game_id)`, `tag(game_id, decision_id, tag)` and `read_media(game_id, name)` enforce the stored game's review lock. Media must have a keyframe or video reference in that game's log. Tags accept only known decision IDs and `agree`, `disagree` or `unsure`; they remain separate from regenerated content. Publication and reads reject changed log evidence. The low-level SessionStore `read_media` remains available for raw capture and offline training; UI and review routes must use the review facade. Internal replay and harness consumers can process locked records, while ticket 42 must suppress their detailed report content.

SessionStore cache methods accept the additive `cache_identity` keyword. `write_review` accepts `expected_log_hash` for guarded publication. Existing callers retain their original signatures. Public tests use temporary SessionStore/DataStore files, the actual Engine, and temporary detached Git worktrees with matching runtime sources. They establish software behavior; no owner-game accuracy, real-game latency, model fitting or Windows qualification is claimed.
